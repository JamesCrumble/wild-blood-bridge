# Как переносилась Wild Blood: разбор по шагам

English version: [PORTING_GUIDE.en.md](PORTING_GUIDE.en.md).

Этот файл — запись того, как игра была доведена от «APK и архив кэша» до главного меню на телефоне, в виде
руководства для следующего такого переноса. Каждый шаг описан одинаково: что было видно, как нашли причину,
что и где исправили. Команды приведены так, чтобы их можно было повторить.

Состояние на 2026-10-13: главное меню, 60 кадров/с на OnePlus 13s. Всё, что после меню, не проверено.
Короткая сводка — в [README.md](../README.md), текущее состояние и список недоделанного —
в [PROJECT_STATE.md](../PROJECT_STATE.md).

## С чего начинать

Каркас (qemu, APK-обёртка, GL-мост, загрузчик) берётся из самого близкого готового проекта целиком и
переименовывается. Здесь это был TDKR Bridge. Переписывается только слой игры в `port/game/`.

Первым делом выясняется, что за игра внутри, — от этого зависит, сколько каркаса подойдёт без изменений:

```sh
unzip -l gamebin/<игра>.apk | grep -v res/          # какие библиотеки лежат в APK
readelf -hd lib.so | grep -E 'NEEDED|SONAME'        # от чего зависит и как себя называет
readelf --dyn-syms -W lib.so | awk '$7=="UND"{print $8}' | sort > extracted/imports.txt
readelf --dyn-syms -W lib.so | grep -E 'Java_|JNI_OnLoad'      # точки входа
dexdump -d classes.dex > extracted/classes.txt      # Java-сторона
strings -n 6 lib.so > extracted/strings.txt
```

У Wild Blood библиотека называется `libUnrealEngine3.so`, а её SONAME — `libAOWGame-Android-Release.so`. Это
Unreal Engine 3, а не движок Gameloft, как в N.O.V.A. 3 и TDKR, поэтому слой игры пришлось писать заново.

Три вопроса, на которые нужно ответить до первой строки кода:

1. **В каком порядке Java вызывает нативные функции.** Смотрится в dex. `tools/dexmethod.py <класс> [метод]
   --calls` печатает только вызовы метода. Здесь порядок такой: `Game.nativeInit` →
   `GameRenderer.nativeInit(производитель, ширина, высота, версия)` → `nativeResize` → `nativeRender` в цикле.
2. **Какие методы Java вызывает сама библиотека.** Имена лежат в строках библиотеки одной группой, сигнатуры
   берутся из dex. Поиск по имени и сигнатуре в фиктивном JNI точный, поэтому сигнатуры нельзя писать по памяти.
3. **Что делает каждая точка входа.** `tools/dis.sh <адрес> <длина>` дизассемблирует участок. У этой библиотеки
   сохранены имена функций, так что видно, что `nativeRender` — это `appUpdate`, которая на первом вызове
   выполняет `appInit`, а дальше `FEngineLoop::Tick`.

## Как искать причину падения

Порядок действий один и тот же:

1. Запустить и взять из лога адрес падения: `pc = … (libUnrealEngine3.so+0x…)`.
2. Найти функцию по адресу в `extracted/syms.txt` и дизассемблировать место: `tools/dis.sh <адрес> 60`.
3. Если указатель берётся через GOT — вычислить слот и найти его в `readelf -rW`; значение слота искать в
   таблице символов. Так находятся глобальные переменные по именам. Пример разобран ниже.
4. Исправлять причину там, где она возникает, а не место падения.

Сначала проверяется запуск на ПК (`tools/run_pc.sh <кадры>`): он за секунды ловит падения на старте. До
картинки на ПК эта игра не доходит — компиляция шейдеров под программным рендером занимает десятки минут.
Всё, что связано с картинкой и скоростью, проверяется только на телефоне.

Долгие прогоны запускаются в фоне с ограничением по времени, лог читается разовыми короткими командами.

### Пример: от адреса падения до имени переменной

Падение из шага 2: `pc = +0x014c8950`, инструкция `str r2, [r3]`, в `r3` ноль. Выше по коду:

```
14c890c  ldr r8, [pc, #2880]    ; смещение до таблицы GOT, лежит по адресу 0x14c9454
14c8918  ldr r3, [pc, #2876]    ; смещение слота внутри GOT, лежит по адресу 0x14c945c
14c891c  add r8, pc, r8         ; r8 = 0x14c891c + 8 + [0x14c9454]
14c8934  ldr r3, [r8, r3]       ; r3 = содержимое слота = адрес переменной
14c8940  ldr r3, [r3]           ; r3 = значение переменной (ноль)
14c8950  str r2, [r3]           ; запись по нулю
```

Слот считается так: `0x14c891c + 8 + слово_по_0x14c9454 + слово_по_0x14c945c`. Получается `0x1e61538`.
Затем две команды:

```sh
readelf -rW libUnrealEngine3.so | grep -i '^01e61538'   # R_ARM_RELATIVE: в слоте лежит адрес
grep -i '^01f78afc' extracted/syms.txt                  # 01f78afc 4 OBJECT lockPointer4
```

Значение слота (`0x1f78afc`) читается из файла по тому же смещению: у этой библиотеки адреса первого
сегмента совпадают со смещениями в файле, второго — тоже (проверяется по `readelf -lW`).

Полная таблица символов, включая локальные, снимается командой `readelf -sW`. В ней 280 тысяч записей
против 76 тысяч в динамической, и именно там нашлись `callSwapBuffers` и `PlatformSwapBuffers` (шаг 8).

## Шаги

### 1. Библиотека не загружается

- **Видно:** `Failed to load module 'libjnigraphics.so'`, затем 11 строк `unresolved symbol`.
- **Причина:** загрузчик считает отдельным модулем всё из DT_NEEDED, чего нет в его списке системных
  библиотек. Неразрешённые символы — внутренности stdio из bionic (`__sfp`, `__sinit`, `__sflags`,
  `__smakebuf`, `__swsetup`, `__swbuf`, `__sglue`, `__sdidinit`) и три функции `AndroidBitmap_*`.
- **Исправление:** библиотека добавлена в `so_builtin_libs` в
  [symtab.cpp](../port/portbase/src/symtab.cpp); символы получили реализации в
  [stdio.cpp](../port/portbase/thunks/libc/stdio.cpp) и
  [libc_table.cpp](../port/portbase/thunks/libc/libc_table.cpp). Заглушки пишут в лог адрес вызова — это
  пригодилось на шаге 4.

### 2. Падение в `Game.nativeInit`: защита GDRM

- **Видно:** `SIGSEGV at 0x00000000`, `pc = +0x014c8950`, девятая группа инструкций функции.
- **Как нашли:** в дизассемблере `str r2, [r3]`, где `r3` прочитан через GOT. Слот GOT `0x1e61538`
  содержит `0x1f78afc`, в таблице символов это `lockPointer4`; рядом `lockPointer1..3`.
- **Причина:** GDRM — проверка лицензии Gameloft. На Android её выполняет активити-установщик до старта игры
  и кладёт результат в четыре глобальных указателя. Установщик у нас не запускается (сервер лицензий давно
  выключен), указатели остаются нулевыми, а движок пишет по ним без проверки.
- **Исправление:** четырём указателям выдано по слову памяти — `wb_unlock_drm` в
  [patch.cpp](../port/game/patch.cpp). Код игры не правится. То же решение применено в N.O.V.A. 3.
- **Не проверено:** читает ли движок эти слова позже как признак лицензии.

### 3. Не хватает методов Java

- **Видно:** строки `Class Game does not have static method …`, `Class String does not have method getBytes`.
- **Исправление:** 64 статических метода класса `Game` и классы `SUtils`, `Device`, `GameInstaller`,
  `C2DMAndroidUtils`, `PortingJNI` — в [game_classes.cpp](../port/game/jni/game_classes.cpp);
  `String.getBytes(charset)` — в [string.cpp](../port/portbase/jni/classes/string.cpp).
- **Правило:** почти все методы отвечают самой тихой разумной константой. Настоящую работу делают немногие:
  `GetTextureFormat` (всегда ETC: в кэше только `CookedAndroid_ETC`), `getConfig` (профиль качества),
  `EglSwapR`, ролики.

### 4. Падение в собственном `fopen` библиотеки

- **Видно:** `bionic stdio internal __sflags() was called from 0x…`, затем `SIGSEGV` на `+0x01a0ecf4`.
- **Как нашли:** адрес вызова попал в функцию `fopen`, определённую в самой библиотеке (`0x1a0f26c`). Список
  таких функций получен выборкой символов в диапазоне `0x1a0a000–0x1a4c000` из `extracted/syms.txt`.
- **Причина:** в библиотеку вкомпилирована libc из CrystaX со своей копией stdio. Её `fopen` берёт `FILE` у
  bionic через `__sfp()` и сам заполняет поля. А функции, которые библиотека по-прежнему импортирует
  (`fprintf`, `getc`, `ferror`, `setvbuf`), попадают на мост загрузчика, где `FILE` — это обёртка над
  потоком хоста. Один и тот же файл открывался бы одним семейством функций, а читался другим.
- **Исправление:** `wb_bridge_private_stdio` в [patch.cpp](../port/game/patch.cpp) ставит перехват на 17
  экспортированных функций (`fopen`, `fclose`, `fread`, `fwrite`, `fseek`, `ftell`, `fgets` и другие) и
  отправляет их туда же, куда пошёл бы импорт с тем же именем. Вызывается до статических инициализаторов.
- **Что оставлено как есть:** функции для широких символов и внутренние (`__sfvwrite`, `__vfwprintf`):
  `vswprintf` и `swscanf` работают со строковыми буферами и с настоящими файлами не встречаются.

### 5. Падение в сетевом потоке

- **Видно:** `SIGSEGV at 0x00000004` в фоновом потоке, `pc` в `FSocketSubsystemBSD::GetHostByName`.
- **Как нашли:** функция читает `[r3, #24]` как адрес узла. В bionic по этому смещению `ai_addr`, в glibc —
  `ai_canonname`, который равен NULL. Поля в `struct addrinfo` у двух библиотек стоят в разном порядке.
- **Исправление:** `getaddrinfo`, `freeaddrinfo` и `gethostbyname` отвечают «нет сети» —
  [symtab_net.cpp](../port/portbase/src/symtab_net.cpp). Игра идёт по своей ветке «интернет отсутствует».
- **Решение по серверу:** мок-сервер Gameloft не делается, пока не найдена прямая зависимость игры от
  сервера. Если понадобится: искать сервер в локальной сети на фиксированном порту 0,5 с, иначе поднимать
  свой внутри приложения.

### 6. Игра не находит свои данные

- **Видно:** падений нет, кадры идут, но ничего не грузится: `textures=0`.
- **Как нашли:** в логе обращений к файлам (`grep 'io: open' logs/pc_run.log`) движок открывает
  `/data/data/<пакет>/AOWGame/CookedAndroid_ETC/Coalesced_INT.bin` и получает ENOENT. Метод `getSDFolder`
  из Java он при этом не вызывает.
- **Исправление:** правило в `port_fix_path` — весь `/data/data/<пакет>` отображается на папку кэша
  ([io_paths.cpp](../port/game/io_paths.cpp)). Сохранения, настройки и лог движка оказываются там же.
- **Что это дало для диагностики:** движок начал писать собственный лог `AOWGame/Logs/Launch.log`. По нему
  видно выбранный формат текстур, версию («1.1.4d», хотя файл APK назван 1.1.5) и то, что инициализация
  растянута на несколько кадров — десяти кадров прогона ей не хватает.

### 7. Игра на телефоне завершается с кодом 1

- **Видно:** в `wb.log` на телефоне `unresolved symbol` для `glDetachShader`, `glGetBooleanv`, `glIsShader`,
  `glFinish`.
- **Причина:** на ПК эти функции даёт настоящий драйвер, а на телефоне все вызовы GL идут через мост, в
  таблице которого их не было.
- **Исправление:** `glDetachShader` добавлен в генератор [gen_glbridge.py](../port/android/tools/gen_glbridge.py)
  (он пишет обе стороны моста), остальные три реализованы на стороне игры в
  [gl_bridge.cpp](../port/portbase/src/gl_bridge.cpp).
- **Проверка наперёд:** все GL-импорты игры сверяются с таблицей моста одной командой, чтобы не ловить
  пропуски по одному:

```sh
for f in $(grep '^gl' extracted/imports.txt); do
  grep -qE "E\($f\)|X\($f\)|\"$f\"" port/portbase/src/gl_bridge.cpp port/portbase/src/gl_bridge_gen.inc \
    || echo "MISSING $f"
done
```

### 8. Чёрный экран и 0 кадров

- **Видно:** счётчик `frames` растёт, `presented` стоит на 0 или 1; обёртка показывает «Подготовка».
- **Ложный след:** сначала подозревался ролик-заставка: игра просит Java проиграть `LevelMovie1`, а плеера
  нет. Добавлено подтверждение остановки ролика (`JavaCallback_StopVideo` → `videoFinished`). Правка
  оставлена, но экран она не оживила.
- **Как нашли:** в полной таблице символов (`readelf -sW`, включая локальные) найдены `callSwapBuffers`,
  `callSwapBuffersR` и `PlatformSwapBuffers(FES2Viewport*)`. Последняя состоит из одной инструкции `bx lr`
  (`+0x014aa05c`).
- **Причина:** Gameloft убрала показ кадра из движка. На Android кадр показывает `GLSurfaceView`: она делает
  swap после каждого возврата из `onDrawFrame`, то есть после каждого `nativeRender`. `Game.EglSwap()` в
  Java пустой, а `EglSwapR()` — дополнительный показ на экранах загрузки. Порт ждал показа только через
  `EglSwapR`.
- **Исправление:** кадр показывается после каждого `nativeRender`, если движок не показал его сам внутри
  кадра — [main.cpp](../port/game/main.cpp).
- **Вывод на будущее:** кто делает swap, нужно выяснять в самом начале. В TDKR его делает порт после `step`,
  здесь на Android его делает вид, а не игра.

### 9. Не найден класс `android/view/KeyEvent`

- **Видно:** `FindClass: no fake class registered for 'android/view/KeyEvent'` и серия
  `GetStaticFieldID: NULL class`.
- **Причина:** функция движка `initMap()` читает 72 константы `KEYCODE_*` через `GetStaticIntField`, чтобы
  построить таблицу клавиш.
- **Исправление:** класс с этими полями добавлен в [wb_classes.h](../port/game/jni/wb_classes.h) и
  [game_classes.cpp](../port/game/jni/game_classes.cpp). Заодно исправлено чтение статических числовых
  полей в [jni.cpp](../port/portbase/jni/jni.cpp): оно возвращало адрес поля вместо значения.
- **Не проверено:** правка собрана в APK, но на телефоне ещё не запускалась.

## Справочник по этой игре

### Точки входа, которые вызывает порт

| Функция | Что это в библиотеке | Когда |
|---|---|---|
| `JNI_OnLoad(vm)` | запоминает `JavaVM`, инициализирует звук (`VoxSetJavaVM`) | один раз |
| `Game.nativeInit()` | ищет все методы Java по именам, пишет в слова GDRM | один раз |
| `GameRenderer.nativeInit(производитель, ширина, высота, версия)` | запоминает размеры и строку версии | один раз |
| `GameRenderer.nativeResize(ширина, высота)` | `glViewport` | один раз |
| `GameRenderer.nativeRender()` | `appUpdate`: первый раз `appInit`, далее `FEngineLoop::Tick` | каждый кадр |
| `GameGLSurfaceView.nativeOnTouch(действие, x, y, палец, времяМс)` | `appOnTouch`: очередь под мьютексом | на касание |
| `Game.nativeOnKeyDown/Up(код)` | клавиши | на нажатие |
| `MyVideoView.videoFinished()` | сбрасывает флаг «ролик идёт» | после ролика |

Производитель передаётся числом, как его считает `Game.getManufacture()` в dex: 0 — прочие, 1 — motorola,
2 — samsung, 3 — htc, 4 — sony, 5 — sharp. Порт передаёт 2.

Действие касания: 1 — палец вниз, 2 — движение, 0 — палец вверх. Внутри `appOnTouch` они переводятся в
коды движка таблицей из трёх чисел: `1 → Began`, `2 → Moved`, `0 → Ended`.

### Что отвечают методы Java

Всего 64 статических метода класса `Game`. Значимые:

| Метод | Ответ порта | Почему |
|---|---|---|
| `GetTextureFormat()` | 4 (ETC) | родная Java выбирает первый из PVRTC (1), ATC (2), DXT (3), ETC (4), что объявляет драйвер. Adreno объявляет ATC, а в кэше только `CookedAndroid_ETC` |
| `getConfig()` | 3 | профиль качества; родная Java ставит 3, 4, 5, 6, 8 или 10 по модели GPU и экрана |
| `getSDFolder()` | папка кэша | движок его не вызывает (шаг 6), оставлен для порядка |
| `isWifiEnabled()`, `NetIsEnable()` | 0 | сети нет |
| `GetPhoneLanguage()` | 0 | индекс языка в таблице игры |
| `JavaCallback_StartVideo(имя)` | сразу «ролик закончился» | плеера нет |
| `JavaCallback_StopVideo()` | «ролик закончился» | родная Java закрывает плеер, и тот сообщает об окончании |
| `EglSwap()` | ничего | в родной Java метод пустой |
| `EglSwapR()` | показать кадр сейчас | экраны загрузки |
| `GetBitmapFromText(…)` | пусто | текста системным шрифтом нет |

Значения переопределяются через `engine_env.txt`: `WB_TEXTURE_FORMAT`, `WB_CONFIG`, `WB_LANG_INDEX`,
`WB_GPU_NAME`.

### Инициализация растянута на кадры

`appInit` вызывает `FEngineLoop::InitStepbyStep`, и запуск продолжается несколько вызовов `nativeRender`.
На телефоне от старта до главного меню около минуты: движок читает кэш шейдеров
(`AOWGame/CookedAndroid_ETC/Shaders/…`) и компилирует программы. За это время мост исполняет около
68 тысяч запросов расположения uniform-переменных. Прогон в 10–20 кадров ничего не показывает.

## Телефон

- Данные копирует `tools/push_data.sh`: APK игры и распакованный кэш без `main.*.obb` (это те же файлы одним
  zip-ом, игре он не нужен), 1,6 ГБ.
- Папки, созданные `adb push` и `adb shell mkdir`, принадлежат пользователю `shell` и закрыты приложению.
  Скрипт ставит `2777` на все папки, включая папку самого приложения, если она создана до установки APK.
- Папки, которые создаёт сам движок, получают права `0744` и недоступны adb. Переходник `mkdir` в
  [symtab_io.cpp](../port/portbase/src/symtab_io.cpp) открывает их, иначе лог движка с телефона не прочитать.
- `tools/build_install.sh` собирает порт и APK, ставит его и перезапускает игру сразу в игру, минуя экран
  настроек. `tools/pull_log.sh` забирает лог, `adb exec-out screencap -p` — снимок экрана.
- В логе с телефона первым делом смотрится строка `frames=N presented=N` и строка `[gl] frames`.

## Что осталось

- Проверить всё после главного меню: кампанию, касания в игре, звук, сохранения, паузу и возврат в приложение.
- Ролики не проигрываются: вступление и концовка пропускаются.
